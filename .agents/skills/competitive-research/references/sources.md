# 情报来源与检索式模板

> 供 `competitive-research` skill 第 1 步使用。

## 1. 六类来源（按可靠性排序）

| # | 来源 | 具体渠道 | 能拿到 | 可靠性 |
|---|---|---|---|---|
| 1 | **源码与仓库** | GitHub/GitLab：commit 活跃度、issue 讨论、PR、`CHANGELOG`、`LICENSE`、star 趋势 | **技术路线 + 存活状态 + 真实痛点（issue 区）** | **最高**（一手） |
| 2 | **更新日志 / roadmap** | release notes、`docs/roadmap.md`、里程碑 issue | **最准确的功能事实与演进方向** | **最高** |
| 3 | **官方文档 / 定价页** | 官网、docs、pricing | 定位主张、能力清单、商业模式 | 高（有营销滤镜） |
| 4 | **用户声音** | 应用商店评论、G2/Capterra、Reddit/HN、论坛、issue 区抱怨 | **真实痛点（比功能表有用）** | 中高（有偏样本） |
| 5 | **招聘信息** | 公司招聘页、LinkedIn | **领先指标**：招什么岗 = 即将做什么（招 AI/ML → 要上 AI 功能；招合规 → 要进受监管市场） | 中（需推断） |
| 6 | **二手分析** | 行业报告、媒体、聚合站、博客 | 背景与快速概览 | **低**（常有过期/SEO 内容，必须找到一手源） |

### 中文场景补充渠道

- **竞品帮助文档与更新日志** —— 最准确的功能细节来源；
- **应用商店评论 / 小红书 / 知乎 / V2EX** —— 中文用户的真实表达；
- **GitHub 中文开源项目** —— 技术路线与许可证一目了然；
- **脉脉 / 招聘网站** —— 团队规模与方向。

## 2. 检索式模板

### 找竞品（第一轮，广撒网）

```
<场景关键词> open source alternative github 2026
<场景关键词> 开源 替代 推荐
best <品类> tools 2026 comparison
<竞品名> vs <竞品名>
```

### 挖单竞品（第二轮，聚焦）

```
<竞品名> github                    → 仓库、活跃度、许可证
<竞品名> changelog / release notes → 演进方向
<竞品名> architecture / docs       → 技术路线
<竞品名> issues <痛点关键词>        → 真实短板
site:github.com <竞品名>           → 直接定位仓库
```

### 找决策依据（第三轮，深度）

```
<竞品名> shuts down / archived / discontinued   → 存活状态（⚠️ 必查）
<竞品名> license                                 → 借鉴边界
<技术方案> benchmark accuracy comparison         → 可量化的技术结论
<竞品名> postmortem / lessons learned            → 失败原因（最有价值）
```

> **⭐ 特别推荐查 "shutdown / archived / postmortem"**：
> 一个项目的**失败原因**往往比它的功能列表更有借鉴价值，而且这类信息几乎没人收集。

## 3. 每个竞品必填的最小字段

```yaml
name:            <名称>
url:             <仓库或官网>
license:         <MIT / Apache-2.0 / AGPL-3.0 / 自定义 —— 决定借鉴边界>
stars_or_users:  <规模，标注日期>
last_activity:   <最后提交 / 最后发布 —— ⚠️ 必填，用于判断存活>
status:          active | stale | archived | discontinued
positioning:     <他们自己怎么说>
tech_stack:      <关键技术选型>
known_weakness:  <issue 区 / 评论里反复出现的问题>
```

## 4. 可靠性标注约定

| 标记 | 含义 |
|---|---|
| （无标记） | 一方来源（源码、release notes、官方文档） |
| `[未验证]` | 二手来源，未找到一手出处 |
| `[推测]` | 由间接证据推断 |
| `[日期]` | 数据有保质期（star 数、定价、版本号）**必须标日期** |

> **禁止**：把 `[推测]` 写成事实。评审者一旦发现一处编造，整份分析的可信度归零。

## 5. 归属红线（借鉴别人项目时）

| 许可证 | 能否借鉴 | 说明 |
|---|---|---|
| MIT | ✅ 最宽松 | 保留版权声明 |
| Apache-2.0 | ✅ | 保留 NOTICE |
| **AGPL-3.0** | ⚠️ **网络 copyleft** | 修改后若对外提供服务需开源；**读思路安全，复制代码不安全** |
| 自定义 / 商业 | ⚠️ 先读原文 | 有的限制商用 |

**铁律**：
- **想法、架构、设计模式不受版权保护** —— 读代码学设计是安全的；
- **具体代码实现受保护** —— 复制粘贴不行；
- 引用他人结论**必须标注来源**；
- **代码归属的清晰程度比技术收益更重要** —— 署名与来源是长期信誉的基础。
