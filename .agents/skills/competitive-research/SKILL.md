# 竞品研究（Competitive Research）

把"看看别人怎么做"变成**可执行的产品决策**。

**这个 skill 存在的理由**：80% 的竞品分析文档写完即被束之高阁，因为它们回答了"别人有什么"，
却没有回答决策者真正关心的"**所以我们应该怎么做**"。产出必须以前者为手段、以后者为目的。

---

## 核心原则（4 条，违反任一条即视为产出不合格）

1. **证据优先**：每条关于竞品的陈述都要带来源（URL + 访问日期）。
   **禁止编造竞品数据。** 无法核实的标注 `[未验证]`，推测的标注 `[推测]`。
2. **诚实优先**：竞品更强的地方**如实写**。一份从不显示自己输的对比没有任何可信度。
3. **买方视角**：按"**用户/招聘方关心的能力**"分组，不按内部架构分组。
   评"**做得怎么样**"（质量差异），不只是"有没有"（功能存在与否）。
4. **导向行动**：每条结论必须落到"**因此我们要做什么 / 不做什么**"。
   没有行动项的竞品分析等于没做。

## Workflow

### 第 0 步 · 界定竞品集合（**四层，绝不能只列直接竞品**）

| 层 | 定义 | 例子 |
|---|---|---|
| **直接竞品** | 同需求、同用户、相似形态 | 同类开源项目 / 同类产品 |
| **间接竞品** | 同需求、不同形态 | 另一种技术路线的同类工具 |
| **替代竞品** | 争夺同一份预算/时间/注意力 | 手工流程、Excel、通用大模型、**"什么都用 Notion 记"** |
| **⭐ 不消费（non-consumption）** | 用户**什么都不做** | **⚠️ 通常这才是最大的竞品** |

> **经典案例**：Uber 最大的对手不是其他打车 App，而是"**拥有一辆私家车**"这件事。
> **对本项目的含义**：学生"不用任何工具、手动翻 PDF"才是最大的竞品，而不是另一个 RAG 项目。

**资源有限时**：选 **1–2 个直接竞品 + 1–2 个参照竞品**，精而不在多。
**注意**：参照竞品可以是相邻领域里"做得好、值得抄"的项目（不一定是竞争者）。

### 第 1 步 · 情报收集（6 类来源，**优先并行**）

| 来源 | 能拿到什么 | 优先级 |
|---|---|---|
| 官网 / README / 产品页 | 定位主张、能力清单 | 高 |
| **更新日志 / roadmap / release notes** | **最准确的功能事实与演进方向** | **最高** |
| **GitHub 仓库**（commit 活跃度、issue、star 趋势、许可证） | **技术路线 + 存活状态** | **最高** |
| 用户评价（应用商店 / 论坛 / issue 区抱怨） | 真实痛点（比功能表有用） | 高 |
| 招聘信息 | **领先指标**：招什么岗 = 马上要做什么 | 中 |
| 定价 / 商业模式 | 单位经济与定位 | 中（非商业项目看托管成本） |

**并行化**：把每个竞品/每个维度当作独立任务并行收集，再统一去重打分。
不要串行地一个竞品读到底。

### 第 2 步 · 能力矩阵打分（**评质量，不评有无**）

**档位**（四档，比 1–5 分更容易对齐、更少假精确）：

| 档位 | 含义 |
|---|---|
| **Strong** | 核心能力，做得明显好 |
| **Adequate** | 够用，无明显短板 |
| **Weak** | 有但很弱 / 有坑 |
| **Absent** | 没有 |

**行怎么选**：
- **8–12 行**，按"用户关心的能力"分组（**不要 40 行功能大表**——它两周就过期，也没人读第 8 行以后）；
- 只详列**关键差异点**，人人一样的行可以合并；
- 每格如有可能标注**证据来源**。

### 第 3 步 · ⭐ 三分类（这张表的产出价值最高）

把每一行归入三类之一 —— **这是决定"我们做什么"的核心依据**：

| 分类 | 定义 | 决策含义 |
|---|---|---|
| **Table stakes**（入场券） | 人人都是 Strong | **必须做，但不构成优势**；做不好直接出局 |
| **Differentiators**（差异化） | 我们 Strong、别人 ≤ Adequate | **主打卖点**，要写进定位与对外材料 |
| **Opportunities**（空白） | **无人领先** | **最值得投入**；也可能是"没人做说明没需求"，需交叉验证 |

> ⚠️ **关键检验**：一个能力只有在**目标用户真的在意**时才算差异化。
> "我评 Strong 但用户觉得可有可无"的，不是优势。

### 第 4 步 · 定位图（2×2）

**选轴原则**：选**能揭示战略差异**的两轴，且基于**外部感知**而非自我评价。

常见轴组合（选一对）：简单↔复杂 × 低价↔高价；单点方案↔平台 × 窄↔广；
本地/自主↔云端/托管 × 通用↔垂直；技术门槛低↔高 × 个人↔团队。

**坐标点大小**可用 star 数 / 融资额 / 用户量表示。
**要读出的东西**：哪个象限**拥挤**（别进）、哪个象限**空白**（机会）。

### 第 5 步 · 差异化定位策略（三选一，明确写出来）

| 策略 | 做法 | 例子 |
|---|---|---|
| **正面竞争（Head-to-Head）** | 在对方最强的维度上做得更好 | Figma 以实时协作对抗 Adobe |
| **差异化（Differentiation）** | 在某个单点做到极致、有明显主张 | Linear 以"有主见、快、漂亮"对抗 Jira |
| **利基（Niche）** | 只服务一个极窄人群 | Superhuman 只服务每天处理 100+ 邮件的重度用户 |

> 对个人 / 小团队项目，**利基通常唯一可行**。正面竞争的工程量不是一个人能承担的。

### 第 6 步 · 行动转化（三时间地平线 + 权重）

| 地平线 | 周期 | 特征 |
|---|---|---|
| **速赢** | 0–4 周 | 低投入、可立即展示 |
| **中期** | 1–3 月 | 构建关键能力 |
| **战略** | 3–12 月 | 结构性变化 |

**优先级权重**（按需调整）：竞争影响 40% / 用户需求 30% / 实施难度 20% / 收益影响 10%。

**行动必须具体到可执行**：
- ❌ "应该改善用户体验"
- ✅ "把上传后的等待从无反馈改成三段式进度提示，目标把用户中途放弃率从 X 降到 Y"

### 第 7 步 · 反向检查（**必做，否则产出会被当作营销材料**）

- [ ] 有没有**竞品比我们强**的地方被略过了？
- [ ] 有没有**我们自己处于 Weak/Absent** 的行？如实标了吗？
- [ ] 有没有把**未验证的推测**写成了事实？
- [ ] 定位图里我们是不是被放在了一个**没有依据的有利象限**？
- [ ] 有没有考虑 **non-consumption**？
- [ ] 是否检查了**存活状态**（归档 / 停更 / 关停）？—— 死掉的项目不该被当成竞争对手。

## 输出格式（内联模板，照此结构产出）

```markdown
# <产品方向> 竞品分析

> 调研日期：YYYY-MM-DD ｜ 来源可靠性：<说明> ｜ 每条结论的核实状态已标注

## 0. 结论先行（三句话）
<我们该做什么 / 不该做什么 / 最大的风险>

## 1. 竞品集合（四层）
| 层 | 竞品 | 存活状态 | 一句话定位 |

## 2. 能力矩阵
| 能力（用户视角） | 我方 | 竞品A | 竞品B | 证据 |
（档位：Strong / Adequate / Weak / Absent）

## 3. 三分类
### Table stakes（必须做）
### Differentiators（主打）
### Opportunities（空白，需验证需求）

## 4. 定位图
<2×2 描述 + 坐标 + 拥挤/空白象限解读>

## 5. 定位策略
<正面竞争 / 差异化 / 利基，选一个并说明理由>

## 6. 行动清单
| 行动 | 地平线 | 优先级分 | 依据 |

## 7. 诚实检查
<竞品更强的地方 / 我们更弱的地方 / 未验证项>

## 8. 来源
| 结论 | 来源 | 可靠性 |
```

## 常见陷阱（逐条对照，中招即返工）

| 陷阱 | 表现 |
|---|---|
| **只看直接竞品** | 忽略替代层与 non-consumption（Blockbuster vs Netflix 的经典教训） |
| **照抄竞品功能** | 结果永远是跟随者，不是领先者 |
| **只看公开信息** | 没实际试用/读代码就下结论 |
| **分析瘫痪** | 没有时间盒，无限收集资料 |
| **功能表演** | 把"功能存在"当作"功能好用" |
| **幸存者偏差** | 只看活下来的成功者，忽略归档/关停的项目 |
| **确认偏误** | 带着"我们要做这个"的结论去找证据 |
| **静态分析** | 只评估对手**现在**多强，不看**增长多快**（真正危险的是后者） |
| **近因偏差** | 不标注数据日期（定价页、star 数会变） |
| **归属红线** | 借鉴了别人代码却声称原创 —— **借鉴设计思路可以，复制代码不行**（尤其 AGPL 项目） |

## 验证（怎么知道这次分析是合格的）

1. **决策可用**：读完第 0 节就能回答"我们下一步做什么"，不需要再翻原始资料；
2. **可追溯**：任意一条结论都能顺着来源表找到出处；
3. **有反向证据**：至少写出 1 条"竞品比我们强的"和 1 条"我们做不到的"；
4. **有存活状态**：每个竞品都标了最后活跃时间 / 是否归档；
5. **非空 Opportunities**：如果三类里 Opportunities 为空，说明行选得太保守（只选了大家都做的事）。

## 节奏建议

| 频率 | 动作 |
|---|---|
| 每周 15 分钟 | 扫一遍直接竞品的 release notes / commit |
| 每月 | 更新能力矩阵中变化的格子 |
| 每季度半天 | 完整重跑本流程（含重新界定竞品集合） |
| **触发式** | 竞品有大版本发布 / 融资 / 归档时，立即更新 |
